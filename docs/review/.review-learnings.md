# Review Learnings

每行一条：审查中被证伪的误报模式、或团队明确表示不关心的类别。下一轮 deep-review 的 context pack 会读它。

- [2026-08-03] 用 FakeAgentTransport 伪造 transport 事件的测试，不能证明真实协议路径可用——codex `turn/completed` 不带 message，正文只在 `item/agentMessage/delta` 里，凡是消费 TURN_COMPLETED payload 的新代码都要用真实事件序列验证（来源：round 1 三个维度独立命中并回证 VERIFIED）
- [2026-08-03] transport 层会把同一批 delta 合并成一个不限长的 TURN_DELTA 事件，任何"先查长度再整段追加"的累积都不是硬上限，必须按剩余额度切片（来源：round 2 correctness + maintainability）
- [2026-08-03] `refresh_session_status_card` 的 `send_view` 失败无界重试是既有机制（改动前后逐字相同），审查新改动时若命中该路径应标 PreExisting: yes；round 3 曾误标为 no（来源：本方 git show HEAD 对比核实）
- [2026-08-03] 修一个失败路径时容易引入新的失败模式：round 1 修"edit 失败别挪指针"→ round 2 发现"永久失败无界重试"。凡是把 fallback 改成 retry 的修复，都要同时给出重试上限与放弃后的降级路径
- [2026-08-07] `_drain_events` 的 `last_visible_text` 去重水位必须按回合作用域：codex 监听器跨回合常驻（ADR 0060），共享水位会在"连续两回合回答同一句"时静默吞掉第二条回复（来源：round 1 correctness + goalfit 双维度命中，本方脚本复现证实）
- [2026-08-07] 升级脚本用 `git ls-remote` 列 tag 取最新版是错的：release.sh 先推 tag 再建 Release，`gh release create` 失败会留下没有 Release 的 tag（来源：round 1 goalfit + conventions 双维度命中）
- [2026-08-07] deep-review 的 concurrency 维度报"两个并发 _drain_events 会重复告警"是误报：`_start_background_event_drain` 按 handle_id 单飞，生产路径不会出现同 handle 双排水（来源：本方读 __init__.py:9744 核实）
