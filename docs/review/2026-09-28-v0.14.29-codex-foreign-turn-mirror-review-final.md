### 第 2 轮 G1–G6

- G1 暂存回合在排水先结束 / 提交失败后卡在无人读的队列 → 统一交接（规则 3）
- G2 订阅交接时直达消息超车已排队消息 → 交接完成才打开直达
- G3 溢出占位绕过回合上限、单条消息可能极大 → 占位受上限约束，入队存有界副本
- G4 关闭时取消镜像任务，正在发的汇总丢失 → 关闭标记 + 10 秒超时
- G5 部署文档一句话与镜像矛盾 → 已改
- G6 订阅与在途 turn/start 并发时把自己的早期事件交给镜像 → 单一归属判定，在途期间"待定"

G1/G2/G6 根源相同：归属判定散在三处。收拢为 `_foreign_verdict` + `_hand_over_queued_foreign`。

### 第 3 轮

1. 交接没覆盖被取消读取留下的回退缓存 → take_queued 先取 pushback
2. 两次有界读取之间排水仍持有一批消息，订阅交接提前打开直达 → `_draining` 覆盖整个 events()
3. 订阅碰上在途提交，提交成功后没有再交接 → 成功后交接一次
4. 单条消息只截断 item 顶层字符串 → `_bounded_copy`（字符串/列表/嵌套都有上限）
